# Табель — ТОО «ПК Алтын Таға»

PWA для ведения табеля учёта рабочего времени цеха металлообработки с телефона. Один человек (мастер) отмечает часы/коды за всю бригаду; данные хранятся в Google-таблице. Приложение пишет только в лист «Журнал» — печатная форма «Табель» собирается из него формулами.

Ниже — всё, что нужно сделать руками: один раз настроить таблицу и Apps Script, один раз развернуть приложение на хостинг, один раз установить его на телефон.

---

## 1. Подготовка Google-таблицы (один раз)

1. Откройте таблицу: https://docs.google.com/spreadsheets/d/1YKf2CQijRLzUMiPEjuTp-fgdxbcdqtABCHbtG9SLo6U/edit
2. Меню **Расширения → Apps Script**.
3. Удалите содержимое файла `Code.gs` по умолчанию и вставьте туда содержимое файла `apps-script\Code.gs` из этого репозитория (целиком).
4. Сохраните (значок дискеты или `Ctrl+S`).
5. В выпадающем списке функций сверху выберите `setupSheets` и нажмите «Запустить» (▶). При первом запуске Google попросит авторизацию — разрешите доступ к таблице (это ваш скрипт, привязанный к вашей таблице).
6. Проверьте результат: должны появиться листы «Сотрудники», «Коды», «Журнал», «Табель», а старый лист «Октябрь(Объем)» — переименоваться в «Архив_исходный». В логе выполнения (**Просмотр → Журналы**) будет написано, что именно создано.
7. Откройте лист «Сотрудники» и проверьте, что ФИО и должности перенеслись верно (таб. № присвоены по порядку 1…12). При необходимости поправьте вручную — это обычный лист, не журнал. В колонке E «Система оплаты» для каждого сотрудника вручную укажите `оклад` или `сдельная` (выпадающий список) — по этому значению в приложении работает фильтр «Все / Оклад / Сдельная». Можно оставить пустым, если система оплаты ещё не определена — такой сотрудник просто не попадёт ни под один из двух конкретных фильтров, но будет виден в «Все».
8. Откройте лист «Коды» — расшифровки кодов (Б, О, К, ог, до, у и т.д.) являются предположением, поправьте под вашу бригаду при необходимости (колонка B — расшифровка, C — цвет, D — оплачивается ли код).
9. Повторный запуск `setupSheets()` безопасен — если лист уже существует, он пропускается (видно в логе), данные не затираются.

### Если после правки «Коды»/«Сотрудники» нужно пересобрать печатную форму

Меню таблицы **Табель → Пересоздать форму** — обновит формулы и условное форматирование листа «Табель» заново (данные в «Журнале» не трогает).

### Архив месяца

Меню таблицы **Табель → Сохранить месяц в архив** — копирует текущий лист «Табель» в `Табель_<Месяц>_<Год>` со значениями вместо формул (снимок на память, дальше не меняется).

## 2. Публикация веб-приложения Apps Script (один раз)

Таблица открыта только на просмотр, поэтому запись в неё идёт через веб-приложение Apps Script.

1. В редакторе Apps Script (тот же проект, что и выше) — **Развернуть → Новое развёртывание**.
2. Тип: **Веб-приложение**.
3. «Выполнять от имени»: **я** (ваш аккаунт — скрипт работает от вашего имени, поэтому у приложения не должно быть прямого доступа к таблице).
4. «Доступ, у кого есть доступ»: **Все**. ⚠️ В списке есть похожий, но другой вариант — «Все, у кого есть аккаунт Google». Он тоже выглядит рабочим (вы сами, залогиненные в Google, сможете открыть URL в браузере и даже увидите JSON), но приложение с ним не заработает: его запросы идут через `fetch()` без вашей Google-сессии, и Google ответит `401 Unauthorized` + ошибкой CORS в консоли браузера. Нужно именно «Все».
5. Нажмите «Развернуть», разрешите запрошенные доступы.
6. Скопируйте **URL веб-приложения** (выглядит как `https://script.google.com/macros/s/XXXXXXXX/exec`) — он понадобится в настройках приложения на телефоне.

**Если позже видите в консоли браузера (F12) `has been blocked by CORS policy` и `401 (Unauthorized)`, хотя прямой переход по URL в браузере работает** — именно эта причина: откройте **Развернуть → Управление развёртываниями** → ✏️ у активного развёртывания → проверьте «Доступ» = «Все» → версия **«Новая версия»** → «Развернуть» (URL не поменяется).

### PIN-код

1. В редакторе Apps Script — **Настройки проекта** (шестерёнка слева) → **Свойства скрипта** → «Добавить свойство скрипта».
2. Имя свойства: `PIN`. Значение: любой PIN-код на ваше усмотрение (цифры или буквы, как удобно).
3. Сохраните. Этот же PIN потом вводится в настройках приложения на телефоне — без него веб-приложение откажет в любом запросе (и на чтение, и на запись).

### PIN для режима вьюера (необязательно)

Чтобы кто-то (нач. цеха, директор, бухгалтер) мог открыть приложение и видеть все экраны, но не мог ничего отметить/сохранить — заведите второй PIN:

1. Там же, в **Свойства скрипта** — ещё одно свойство с именем `VIEW_PIN`. Значение — другой PIN, отличный от `PIN`.
2. Сохраните и опубликуйте новую версию (см. ниже «Если вы поменяли код `Code.gs` позже» — после изменения `Code.gs` это нужно всегда, но при добавлении только свойства скрипта новое развёртывание не обязательно, т.к. свойства читаются в момент запроса, а не зашиваются в код).
3. На телефоне того, кому нужен только просмотр — в «Настройках» приложения указать тот же адрес веб-приложения, но `VIEW_PIN` вместо `PIN`. Приложение само покажет баннер «Режим только для чтения», спрячет кнопки ввода/сохранения, а сервер (не только интерфейс) откажет в записи даже при прямом запросе с этим PIN.
4. Если свойство `VIEW_PIN` не задано — режима вьюера просто нет, обычный `PIN` по-прежнему даёт полный доступ. Можно завести/убрать `VIEW_PIN` в любой момент, это не ломает уже работающий `PIN`.

### PIN для табельщика, который ведёт только сдельщиков (необязательно)

Для человека, который отмечает часы/коды только сдельщикам (колонка E «Система оплаты» = `сдельная`) и не должен ни видеть, ни трогать окладных:

1. Там же, в **Свойства скрипта** — свойство с именем `TIMEKEEPER_PIN`. Значение — третий PIN, отличный от `PIN` и `VIEW_PIN`.
2. На телефоне табельщика в «Настройках» приложения указать тот же адрес веб-приложения и `TIMEKEEPER_PIN`. Приложение покажет баннер «Табельщик — доступны только сдельщики», список/таблица/«Сдельщикам N ч» сразу сузятся до сдельщиков, переключатель «Оклад»/«Все» не показывается (переключать нечего). Окладные сотрудники в этом режиме не видны вовсе.
3. Граница настоящая, не только в интерфейсе: даже если отправить запрос на запись по сотруднику с системой оплаты «оклад» напрямую (минуя приложение) с этим PIN — сервер (`Code.gs`) его отклонит.
4. Как и `VIEW_PIN`, это свойство необязательное — без него роли табельщика просто нет.

### Если вы поменяли код `Code.gs` позже

Каждое изменение кода требует **нового развёртывания** (Развернуть → Управление развёртываниями → значок карандаша у текущего → «Новая версия» → Развернуть), иначе веб-приложение продолжит работать по старому коду.

## 3. Публикация самого приложения (хостинг)

Файлы приложения — чистые HTML/CSS/JS, сборка не нужна. Выложить можно на GitHub Pages или Netlify.

### Вариант А — GitHub Pages

1. Создайте репозиторий на GitHub, загрузите в него все файлы этой папки (`index.html`, `styles.css`, `*.js`, `manifest.webmanifest`, `sw.js`, `icons\`, и т.д. — `apps-script\`, `tests\`, `*.md` не обязательны, но не помешают).
2. В репозитории: **Settings → Pages → Source** — выберите ветку (`main`) и папку `/root`.
3. Через пару минут приложение будет доступно по адресу вида `https://<ваш-логин>.github.io/<репозиторий>/`.

### Вариант Б — Netlify

1. Зайдите на https://app.netlify.com, «Add new site → Deploy manually».
2. Перетащите папку проекта (или zip-архив с её содержимым) в окно загрузки.
3. Netlify выдаст адрес вида `https://<случайное-имя>.netlify.app` — можно переименовать в настройках сайта.

> PWA (установка на экран, офлайн-режим) требует HTTPS — оба варианта это обеспечивают.

## 4. Настройка приложения

1. Откройте опубликованный адрес на телефоне или компьютере.
2. При первом запуске появится экран настройки — введите:
   - **Адрес веб-приложения** — тот URL `.../exec`, что скопировали в шаге 2.6.
   - **PIN** — тот, что задали в шаге 2 («Свойства скрипта»).
3. Нажмите «Сохранить и продолжить».

Эти настройки хранятся только в `localStorage` телефона — в репозиторий и в код не попадают.

Проверить интерфейс без таблицы можно, открыв адрес с `?demo=1` в конце (например `https://ваш-сайт/index.html?demo=1`) — приложение сгенерирует тестовые данные и будет работать полностью автономно, без сети и без реальной таблицы.

## 5. Установка PWA на телефон

### Android (Chrome)

1. Откройте адрес приложения в Chrome.
2. Меню (три точки) → **«Добавить на главный экран»** / «Установить приложение».
3. Подтвердите — появится иконка, приложение откроется в полноэкранном режиме, без адресной строки.

### iPhone (Safari)

1. Откройте адрес приложения в **Safari** (обязательно Safari, не Chrome — на iOS только Safari умеет устанавливать PWA).
2. Нажмите кнопку «Поделиться» (квадрат со стрелкой вверх).
3. **«На экран «Домой»»** → «Добавить».
4. Приложение появится как обычная иконка и будет открываться без адресной строки браузера.

## 6. Как это устроено (коротко)

- Приложение показывает/редактирует только лист «Журнал» — одна строка на отметку, исправления не удаляют старые строки (действует последняя запись на пару дата+таб.№).
- Лист «Табель» никогда не редактируется приложением — он целиком формулы, которые сами подтягивают последнюю запись из «Журнала» и показывают «В» на пустой воскресной ячейке.
- «Табель» группирует сотрудников по системе оплаты — сперва «оклад», потом «сдельная» (и, если есть сотрудники без назначенной системы оплаты, они последними своей группой), внутри группы — по фамилии. После каждой непустой группы — строка промежуточного итога («Итого (оклад)» / «Итого (сдельная)»), в самом низу — общий «ИТОГО». Первый столбец — порядковый номер по списку (1, 2, 3…), не таб. №; реальный таб. № хранится в скрытом техническом столбце AO, по нему формулы находят часы в «Журнале» — так что порядок строк (а добавление нового сотрудника в любое место «Сотрудники» тоже меняет порядок) никогда не путает, чьи часы показываются.
- Офлайн: справочники и отметки текущего/прошлого месяца кешируются в IndexedDB, несохранённые правки лежат в очереди с уникальным `uuid` и отправляются при появлении сети. Это же `uuid` защищает от задвоения строки, если запрос ушёл, а подтверждение не дошло.
- Конфликт (кто-то/что-то изменило ту же ячейку в таблице уже после того, как приложение её загрузило) — показывается выбор «моё значение» / «из таблицы».
- На экранах «День» и «Месяц» список/таблица всегда отсортированы так же, как «Табель»: сперва «оклад», потом «сдельная» (и, если есть, без категории — последними), внутри группы по фамилии; номер слева от сотрудника — порядковый (1, 2, 3…), не таб. №. При фильтре «Все» между группами показывается заголовок-разделитель («Оклад» / «Сдельная»); при фильтре на одну систему оплаты заголовок не нужен и не показывается.
- На экранах «День» и «Месяц» есть фильтр «Все / Оклад / Сдельная» по колонке E «Система оплаты» листа «Сотрудники» — сужает список/таблицу до одной системы оплаты, в том числе для «Всем N ч» и итогов. Чтобы заполнить часы только сдельщикам (или только окладным) отдельно от остальных — выбрать нужный фильтр и нажать кнопку «Сдельщикам N ч» (она же «Всем»/«Окладным» в зависимости от фильтра): она заполняет только тех, кто сейчас виден в списке.
- Режим вьюера (см. «PIN для режима вьюера» выше): тот же интерфейс, но без кнопок ввода/сохранения — для тех, кому нужно только посмотреть табель.
- Режим табельщика (см. «PIN для табельщика» выше): полноценный ввод, но только для сдельщиков — окладные не видны и не редактируются, граница проверяется на сервере.

Подробности и формулы листа «Табель» — в `PROMPT.md` (раздел 1.2). Список технических решений, принятых по ходу реализации — в `DECISIONS.md`.

## 7. Формулы листа «Табель» (на будущее, если нужно поправить вручную)

Все формулы пишет функция `buildTabelSheet` в `apps-script\Code.gs` — ниже тот же смысл по-русски, для справки. Строки сотрудников нумеруются с 18, но точный номер строки каждой группы и подытога зависит от того, сколько сейчас активных «оклад»/«сдельная» сотрудников — вычисляется в `computeTabelLayout()`, в таблице ниже это обозначено как `<row>`.

- **O11** (строка «За … года», именительный падеж месяца):
  `="За "&ВЫБОР(МЕСЯЦ($AN$11);"январь";"февраль";"март";"апрель";"май";"июнь";"июль";"август";"сентябрь";"октябрь";"ноябрь";"декабрь")&" "&ГОД($AN$11)&" года"` — `AN11` (скрытый) хранит первое число месяца.
- **Строка 14** (числа дней месяца, пример для столбца D):
  `=ЕСЛИ(МЕСЯЦ($AN$11+СТОЛБЕЦ()-4)=МЕСЯЦ($AN$11);$AN$11+СТОЛБЕЦ()-4;"")`
- **Строка 13** (пометка воскресений): `=ЕСЛИ(D14="";"";ЕСЛИ(ДЕНЬНЕД(D14)=1;"В";""))`
- **AO`<row начала группы>`** (скрытый технический столбец, список таб. номеров этой группы системы оплаты, отсортированный по фамилии):
  `=ЕСЛИОШИБКА(СОРТ(ФИЛЬТР(Сотрудники!$A$2:$A$1000;СЖПРОБЕЛЫ(СТРОЧН(Сотрудники!$D$2:$D$1000))="да";СЖПРОБЕЛЫ(СТРОЧН(Сотрудники!$E$2:$E$1000))="оклад");ФИЛЬТР(СЖПРОБЕЛЫ(Сотрудники!$B$2:$B$1000);…те же условия…);ИСТИНА);"")` (для группы «сдельная» — условие по столбцу E меняется на `="сдельная"`, для «без категории» — на `<>"оклад"` и `<>"сдельная"` одновременно).
- **A`<row>`** (порядковый номер) — обычное число (1, 2, 3…), не формула.
- **B/C`<row>`**: `=ЕСЛИОШИБКА(ВПР(AO<row>;Сотрудники!$A:$C;2;ЛОЖЬ);"")` (и колонка 3 для должности).
- **Ячейка дня** (пример D`<row>`, тянется на весь диапазон дней сотрудника):
  `=ЕСЛИ(D$14="";"";ЕСЛИОШИБКА(ИНДЕКС(ФИЛЬТР(Журнал!$C:$C;Журнал!$B:$B=$AO<row>;Журнал!$A:$A=D$14);СЧЁТЕСЛИМН(Журнал!$B:$B;$AO<row>;Журнал!$A:$A;D$14));ЕСЛИ(ДЕНЬНЕД(D$14)=1;"В";"")))`
- **Итоги по строке сотрудника**: AI `=СЧЁТ(D<row>:AH<row>)`, AJ `=СУММ(D<row>:AH<row>)`, AL (переработка) `=СУММ(ЕСЛИ(ЕЧИСЛО(D<row>:AH<row>);ЕСЛИ(D<row>:AH<row>>8;D<row>:AH<row>-8;0);0))` (формула массива), AK и AM — пустые.
- **Подытог группы** (строка сразу после последнего сотрудника группы): AI/AJ/AL — `=СУММ(...)` по диапазону строк этой группы.
- **ИТОГО** (последняя строка): AI/AJ/AL — сумма ячеек подытогов всех групп (а не диапазона всех строк — так подытоги не задваиваются в общей сумме).

```
index.html, styles.css          — разметка и стили

queue.js                        — кеш и офлайн-очередь (IndexedDB)
app.js                          — экраны и интерфейс
sw.js, manifest.webmanifest     — service worker и PWA-манифест
icons\                          — иконки PWA (плейсхолдер, см. DECISIONS.md)
apps-script\Code.gs             — бэкенд (вставляется в Apps Script таблицы)
tests\check.mjs, tests\fixture.json — тесты model.js (node tests\check.mjs)
tests\gen-icons.mjs             — генератор иконок-плейсхолдеров
DECISIONS.md                    — решения, принятые автономно по ходу работы
PROGRESS.md                     — чек-лист выполнения по разделу 6 PROMPT.md
```
